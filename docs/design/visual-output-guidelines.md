# ProjectS 建築・地形ビジュアル提案ルール

- **決定日:** 2026-08-09
- **ステータス:** ProjectS全体の標準ルール

## 1. 最優先ルール

ProjectSで、実際に建築・配置・実装することを前提とした画像を提案するときは、**一般的なファンタジーコンセプトアートではなく、Minecraftのゲーム内で見える姿を基本にする。**

ユーザーが特に評価したのは説明ボードであること以上に、建築と街の見た目がMinecraftのブロック表現・ゲーム画面として示され、実装後の姿を判断しやすかった点である。

## 2. 対象

このルールを優先する対象:

- 町、村、港、拠点
- 建物の外観・内装
- ダンジョン入口、フィールド施設
- 地形、道路、橋、ランドマーク
- Minecraft上で建築する予定の構造物
- Axiom・schematic・WorldPainterへ落とし込む設計案

## 3. 表現基準

- Minecraftのブロック、階段、ハーフブロック、柵、壁、トラップドアなどで成立しそうな形にする。
- 実際のゲーム内スクリーンショット、シェーダー付きMinecraft、または高品質なボクセル建築に近い見た目にする。
- 道幅、高低差、建物密度、入口、内部空間がMinecraftの縮尺として判断できるようにする。
- 現実建築や絵画的ファンタジーをそのまま描かず、ブロックへ翻訳した姿を見せる。
- 実装不能な曲面、極端に細い装飾、巨大すぎる非ブロック造形へ依存しない。
- リソースパックやカスタムモデルが必須な表現は、標準ブロックで成立する部分と区別する。

## 4. 推奨する一枚ボード形式

可能な場合は、次を一枚または一組で示す。

1. **Minecraft風の全体俯瞰・主景観**
2. **上空からの機能配置図**
3. **主要施設ごとの拡大カット**
4. **内部またはプレイヤー視点**
5. **主要導線・高低差・区画番号**
6. **日本語の短い注釈**

ただし、ボード形式そのものよりも、**建築がMinecraftの見た目であることを優先する。**

## 5. 提案時に同時に示す内容

- その場所でプレイヤーが何をするか
- 主要な入口と出口
- 隣接施設との関係
- 普段の移動経路
- 建材・色・目印
- 実用区画と装飾の関係
- Minecraftで再現するときの難所や前提

## 6. 避ける出力

- 一般的なファンタジー都市の絵だけを出す
- Minecraftでの縮尺やブロック構造が判断できない
- 雰囲気は良いが、どこに何があるか分からない
- 巨大な空地や外観専用建築を無自覚に増やす
- 画像内のラベルだけで用途を説明し、建築自体から用途が読めない
- 俯瞰図だけで、プレイヤー視点の見え方を示さない
