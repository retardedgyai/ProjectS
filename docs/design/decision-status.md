## 現在の仕様決定状況

### 完了済み

- ProjectSの必須コンセプト: 共存型MMO
- Beta上限Lv45
- 標準約25時間でLv45
- Lv45到達後、最初の島の最終ボス撃破でエンドゲーム解放
- Beta装備Tier: T1〜T3
- ILv = 装備可能レベル
- 完成装備は基本的に敵から直接ドロップしない
- 製造者が装備ベースを供給
- 使用者がMOD素材で装備を仕上げる
- レアリティ = MOD枠数
- Common 1 / Uncommon 2 / Rare 3 / Epic 4
- MOD Rank 1〜3
- 装備8枠
- 軽装・中装・重装の自由装備
- 防具にも火力MODを付与可能
- 防御を捨てた火力特化は紙装甲になる
- パーティーはLv1から利用可能
- MODは共通MOD + 部位専用・得意MODの混合型
- MODはデータ駆動・タグ駆動で拡張可能にする

### 決定済み攻撃MOD

基礎火力:

1. 攻撃力 +%
2. 与ダメージ +%
3. スキルダメージ +%
4. 通常攻撃ダメージ +%

攻撃タイプ:

5. 近接ダメージ +%
6. 投射物ダメージ +%
7. 魔法ダメージ +%

クリティカル・速度:

8. クリティカル率増加 +%
   - 元のクリティカル率を割合で伸ばす
   - 基礎クリティカル率への直接加算は希少・特殊効果として扱う
9. クリティカル倍率 +%
   - 基本クリティカル倍率150%
   - 基本倍率へ加算する
10. 攻撃速度 +%
   - 武器ごとの基準速度を残しながら伸ばす
11. キャスト短縮 +%
   - 魔法、弓のチャージ、大技の溜め、回復、召喚などの準備時間を短縮する
   - 即時発動スキルには適用しない

適用は武器種ではなく攻撃・行動タグで判定する。

### 決定済み攻撃系統・属性

攻撃系統:

- 物理
- 魔法
- 物理技は物理耐久、魔法技は魔法耐久で計算する
- 属性が付いても参照する耐久値は変わらない

Beta属性:

- 火
- 氷
- 雷
- 光・闇は将来候補

属性の役割:

- 属性による常時直接ダメージ増幅は行わない
- 属性ダメージが増幅されるのは、PvEでモブ・ボスの弱点を突いた時のみ
- 属性差は燃焼、凍結、連鎖などの攻撃性質で表現する
- プレイヤーには属性弱点・属性耐性を持たせない
- PvPでは属性弱点による増幅を発生させない

属性投資ビルド:

- 属性投資は弱点特効と属性固有効果を伸ばす
- 汎用火力・クリティカル型は相手を選ばない安定火力
- 単属性特化は狭く深く、対応ボスと固有効果に強い
- 複数属性型は広く浅く、対応範囲が広い
- 属性投資MODの名称・数値形式・表示方法は未決定

属性注入:

- 装備や攻撃へ火・氷・雷の属性と性質を付与する
- 物理と属性ダメージを別防御で分割計算する方式ではない
- 魔術、魔導工房、触媒、魔術素材、加工と結びつける

複数属性:

- 一つの武器・攻撃が複数属性を持てる
- 防御計算は攻撃系統に従う
- 複数弱点による倍率の重複は行わない方向

### 決定済み貫通・防御対策

基本耐久:

- 物理耐久
- 魔法耐久

採用する貫通:

- 物理貫通 +%
- 魔法貫通 +%

採用しないもの:

- 火・氷・雷の属性貫通
- 属性耐性
- 全属性貫通
- 全耐久貫通
- 固定値貫通

貫通は本人のみ、物理・魔法耐久低下は敵への弱体としてパーティー全員が恩恵を受ける。

### 決定済みスキル・リソース系MOD

1. クールダウン短縮 +%
   - 攻撃、回復、防御、妨害、移動などクールダウンを持つスキル全般が対象
   - 攻撃系ではなく、スキル・リソース系のスキル回転MODとして扱う
   - 必須化は数値幅・部位・出現重みで調整する

## 仕様決めの現在地点

次に決める大項目:

> 状態異常・継続ダメージ系

次回は、以下を一つずつ検討する。

1. 火属性の燃焼をどういう効果にするか
2. 氷属性の減速・凍結をどのように段階化するか
3. 雷属性の瞬間火力・連鎖・感電をどう表現するか
4. 属性投資が状態異常へ何を伸ばすか
5. 状態異常の付与方法を確率・蓄積・スキル固定のどれにするか
6. 同じ状態異常の重複、更新、スタック上限
7. ボスへのCC・状態異常の効き方
8. PvPでのCC耐性、減衰、継続ダメージ調整
9. 継続ダメージがクリティカル・貫通・攻撃系統の影響を受けるか

その後の予定:

1. 条件付き攻撃MOD
2. 防御MOD
3. リソース・回復MOD
4. 機動・操作MOD
5. 特殊MOD
6. 各MODの装着部位・数値幅・抽選重み

## 現在の開発優先順位

仕様決めとは別に、実装作業の現在優先順位はMob Editor UI。

1. Mob Editor UI
2. 装備メタデータ基盤
3. MOD定義・保存基盤
4. 製造基盤
5. 経済・マーケット

仕様決めはMob Editor開発と並行して続けてよいが、実装はこの順番を守る。

## 運用ルール

- 仕様を新しく確定したら、該当設計ファイルを更新する
- 仕様決めの終了時に、このファイルの「現在地点」を更新する
- 新しい案は捨てずに保存するが、実装優先順位は変えない
- 曖昧な部分は勝手に確定せず、未決定として残す
