## 現在の仕様決定状況

### 完了済み

- ProjectSの必須コンセプト: 共存型MMO
- Beta上限Lv45
- 標準約25時間でLv45
- Lv45到達後、最初の島の最終ボス撃破でエンドゲーム解放
- Beta装備Tier: T1〜T3
- ILv = 装備可能レベル
- 完成装備は基本的に敵から直接ドロップしない
- 製造者が装備ベースを供給
- 使用者がMOD素材で装備を仕上げる
- レアリティ = MOD枠数
- Common 1 / Uncommon 2 / Rare 3 / Epic 4
- MOD Rank 1〜3
- 装備8枠
- 軽装・中装・重装の自由装備
- 防具にも火力MODを付与可能
- 防御を捨てた火力特化は紙装甲になる
- パーティーはLv1から利用可能
- MODは共通MOD + 部位専用・得意MODの混合型
- MODはデータ駆動・タグ駆動で拡張可能にする

### 決定済み攻撃MOD

基礎火力:

1. 攻撃力 +%
2. 与ダメージ +%
3. スキルダメージ +%
4. 通常攻撃ダメージ +%

攻撃タイプ:

5. 近接ダメージ +%
6. 投射物ダメージ +%
7. 魔法ダメージ +%

クリティカル・速度:

8. クリティカル率増加 +%
   - 元のクリティカル率を割合で伸ばす
   - 基礎クリティカル率への直接加算は希少・特殊効果として扱う
9. クリティカル倍率 +%
   - 基本クリティカル倍率150%
   - 基本倍率へ加算する
10. 攻撃速度 +%
   - 武器ごとの基準速度を残しながら伸ばす
11. キャスト短縮 +%
   - 魔法、弓のチャージ、大技の溜め、回復、召喚などの準備時間を短縮する
   - 即時発動スキルには適用しない

適用は武器種ではなく攻撃・行動タグで判定する。

### 決定済み攻撃系統・属性

攻撃系統:

- 物理
- 魔法
- 物理技は物理耐久、魔法技は魔法耐久で計算する
- 属性が付いても参照する耐久値は変わらない

Beta属性:

- 火
- 氷
- 雷
- 光・闇は将来候補

属性の役割:

- 属性値は通常攻撃・スキルの属性直撃にも反映する
- 属性値は属性固有効果、弱点特効の基準にもする
- PvEで弱点を突いた場合は追加増幅が発生する
- 属性差は燃焼、凍結、連鎖などの戦闘性質で表現する
- プレイヤーには属性弱点・属性耐性を持たせない
- PvPでは属性弱点による増幅を発生させない

属性投資ビルド:

- 属性投資は属性直撃、弱点特効、属性固有効果を伸ばす
- 汎用火力・クリティカル型は相手を選ばない安定火力
- 単属性特化は狭く深く、対応ボスと固有効果に強い
- 複数属性型は広く浅く、対応範囲が広い
- 固定値は `属性値 +x`
- 割合強化は `属性値 +%`

属性注入:

- 装備や攻撃へ火・氷・雷の属性と性質を付与する
- 防御計算は元の物理・魔法系統に従う
- 魔術、魔導工房、触媒、魔術素材、加工と結びつける

複数属性:

- 一つの武器・攻撃が複数属性を持てる
- 防御計算は攻撃系統に従う
- 複数弱点による倍率の重複は行わない方向

### 決定済み貫通・防御対策

基本耐久:

- 物理耐久
- 魔法耐久

採用する貫通:

- 物理貫通 +%
- 魔法貫通 +%

採用しないもの:

- 火・氷・雷の属性貫通
- 属性耐性
- 全属性貫通
- 全耐久貫通
- 固定値貫通

貫通は本人のみ、物理・魔法耐久低下は敵への弱体としてパーティー全員が恩恵を受ける。

### 決定済みスキル・リソース系MOD

1. クールダウン短縮 +%
   - 攻撃、回復、防御、妨害、移動などクールダウンを持つスキル全般が対象
   - 攻撃系ではなく、スキル・リソース系のスキル回転MODとして扱う
   - 必須化は数値幅・部位・出現重みで調整する

### 火属性の基本仕様完了

火属性の中核:

- 火属性攻撃で燃焼値を蓄積する
- 必要燃焼値ごとに燃焼スタックへ変換する
- 燃焼スタック数に応じて継続ダメージが強くなる
- 最大10スタック
- 10スタック到達で爆燃
- 爆燃時に7スタック消費、3スタック残存
- 燃焼値とスタックは敵ごとの共有状態
- 物理・魔法の貢献割合に応じて燃焼・爆燃を分割計算する

Beta基準:

- 通常モブ: 燃焼値25で1スタック
- ボス: 燃焼値100で1スタック
- 爆燃基本倍率: 有効火属性値の250%
- 爆燃範囲: 半径4ブロック
- 中心ダメージ100%、周囲ダメージ60%
- 素の爆燃は周囲へ燃焼を拡散しない

減衰:

- 最後の燃焼値加算から5秒維持
- その後、端数燃焼値から減少
- 端数は毎秒1スタック必要量の25%ずつ減少
- 端数消滅後、2秒ごとに1スタック減少
- ボスの強制無敵・フェーズ移行中は減衰停止

運用:

- 数値はコード固定にしない
- ゲーム内管理UIで調整可能にする
- カテゴリ標準値とモブ・ボス個別上書きを持つ
- 即時テスト、再読込、ロールバック、変更履歴に対応する方向

火属性は基本戦闘ループまで完了。細かな係数、PvP補正、報酬分配などは実装・バランステスト段階で詰める。

## 仕様決めの現在地点

現在の大項目:

> 氷属性の冷気・減速・凍結・氷砕き

決定済みの方向:

- 氷属性は純粋な妨害属性にはしない
- 冷気を蓄積し、減速から凍結へ進める
- 凍結中は攻撃チャンスとなり、対象へのダメージを増加させる
- 凍結状態を砕くことで大きな氷砕きダメージを与える
- 凍結中に攻め続けるか、早めに砕いて瞬間火力を取るかを選べる属性にする

次に一つずつ決める項目:

1. 冷気を燃焼値と同じ蓄積方式にするか
2. 減速を何段階に分けるか
3. 通常モブ・ボスで凍結条件をどう変えるか
4. 凍結時間
5. 凍結中のダメージ増加倍率と適用対象
6. 氷砕き可能な攻撃条件
7. 氷砕きダメージの基準
8. ボスは完全停止させるか、行動速度低下・ブレイク状態に置き換えるか
9. PvPでの凍結時間、連続CC耐性、氷砕き補正

その後の予定:

1. 雷属性の瞬間火力・連鎖・感電
2. 条件付き攻撃MOD
3. 防御MOD
4. リソース・回復MOD
5. 機動・操作MOD
6. 特殊MOD
7. 各MODの装着部位・数値幅・抽選重み

## 現在の開発優先順位

仕様決めとは別に、実装作業の現在優先順位はMob Editor UI。

1. Mob Editor UI
2. 装備メタデータ基盤
3. MOD定義・保存基盤
4. 製造基盤
5. 経済・マーケット

仕様決めはMob Editor開発と並行して続けてよいが、実装はこの順番を守る。

## 運用ルール

- 仕様を新しく確定したら、該当設計ファイルを更新する
