# ProjectS Codex Task Template

ProjectSのCodex向け実装指示は、簡易Taskまたは完全版Taskとしてこの
テンプレートを使用する。作成者はどちらを使うかを明記し、不明な場合は
完全版Taskを使用する。

## タスク形式

`簡易Task` または `完全版Task`

### 簡易Taskの使用区分

文言修正、小規模なnull check、1ファイル程度の機械的修正、影響範囲が
明確な小さなテスト追加、ドキュメントのみの変更、動作を変えない単純整理
に使用する。必須項目は、推奨モデル、推論強度、目的、スコープ、非対象、
受け入れ条件、テスト、完了報告とする。

### 完全版Taskの使用区分

戦闘計算、経済・報酬・取引、永続化・移行、非同期・並列処理、権限・
セキュリティ、Protocol、複数システム統合、Runtime lifecycle、大規模変更、
高リスク変更に使用する。以下の完全版項目を使用する。

## タスク指示の優先順位

1. ユーザーの明示的な最新指示
2. 承認済みのタスク固有指示
3. より深いdirectoryの`AGENTS.md`/`AGENTS.override.md`
4. repository rootの`AGENTS.md`
5. 一般的な既定動作

タスク固有指示でも、production data保護、force push禁止、無断のmain変更、
無断の配備・起動、スコープ外実装は暗黙に解除しない。解除する場合は、
その操作を明示的に許可する指示が必要である。

## 推奨モデル

`Luna` / `Terra` / `Sol`

モデルと推論強度はタスク開始前にユーザーまたはChatGPTが選択する。
Codex実行中にモデルを自動変更するものではない。指定モデルが利用できない
場合は、勝手に高コストモデルへ変更せず、開始前に制限と利用可能な候補を
報告する。

## 推論強度

`Low` / `Medium` / `High`

## 選定理由（完全版Task）

このモデルと推論強度を選んだ理由を簡潔に記載する。
タスクの曖昧さ、変更範囲、リスク、調査量、トークン効率を考慮する。

## 実装上の制約

- 指定スコープを広げない。
- 関係のないリファクタリングを行わない。
- 既存のProjectS実装パターンを優先する。
- 生成物である`build/`や`.gradle/`を編集しない。
- サブエージェントや高コスト設定は、明示的な許可がある場合だけ使用する。
- 同一worktreeでの複数エージェント同時編集やCodex独断の並列分割も、明示的な
  許可がある場合だけ使用する。ChatGPTが分割した独立Trackは、別branch・
  別worktree・別Codexタスクでの並行開発を許可する。
- ユーザーの最新の明示指示、承認済みタスク固有指示、より深い
  `AGENTS.md`/`AGENTS.override.md`、repository rootの`AGENTS.md`、一般的な
  既定動作の順に従う。タスク固有指示でもproduction data保護、force push禁止、
  無断main変更・配備・起動・スコープ外実装は暗黙に解除しない。
- commit、push、PR作成、Draft解除、merge、branch削除は、タスク固有の明示指示が
  ある場合だけ行う。

## 実装後の報告形式

1. 使用したモデルと推論強度
2. 変更したファイル
3. 実装内容
4. 受け入れ条件ごとの結果
5. 実行したテスト・ビルドコマンド
6. テスト結果
7. 残っている問題・警告
8. 仕様判断または設計判断が必要な点
9. Minecraft内での確認方法

## レビュー方針

以下のいずれかに当てはまる場合は、差分とテスト結果をSolレビューへ渡す。

- 戦闘計算基盤
- 経済・取引・報酬・アイテム複製リスク
- 永続化・移行・プレイヤーデータ
- 非同期・並列処理
- 権限・セキュリティ
- 複数システムをまたぐ変更
- 大規模な差分
- Lunaが失敗または懸念を報告した変更

軽微な変更は、Lunaの自己確認と自動テストで完了してよい。
